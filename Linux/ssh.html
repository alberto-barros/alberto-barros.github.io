Acesso Remoto com SSH

Objetivo: Instalar o servidor SSH no Linux Mint, verificar se o serviço está ativo, descobrir o IP da máquina virtual e acessá-la pelo PuTTY na máquina real. No desafio, você vai entrar usando chaves no lugar da senha.

Passo 00 · VirtualBox da máquina real

Antes de tudo: mudar a rede da VM para Somente Hospedeiro

Faça isto com a máquina virtual desligada. A rede Somente Hospedeiro (Host-only) liga a VM direto à máquina real, e é por ela que o PuTTY vai entrar.

  1. 1

    Confira se a VM está desligada

    Na lista do VirtualBox, a VM precisa aparecer como Desligada. Se estiver ligada, desligue o Linux Mint pelo menu antes de continuar.

  2. 2

    Abra as Configurações

    Selecione a VM e clique em Configurações (ícone de engrenagem).

  3. 3

    Troque o Adaptador 1

    Abra Rede › Adaptador 1. Em Conectado a, troque Placa em modo Bridge por Placa de rede exclusiva de hospedeiro (Somente Hospedeiro / Host-only). Em Nome, escolha vboxnet0.

  4. 4

    Ligue o Adaptador 2 em NAT

    Abra a aba Adaptador 2, marque Habilitar Placa de Rede e escolha NAT em Conectado a. Assim a VM continua com internet para instalar os pacotes.

  5. 5

    Salve e ligue a VM

    Clique em OK e só agora ligue a VM.

A rede interna usa a faixa 192.168.0.x. Confira em Arquivo › Ferramentas › Gerenciador de Rede, aba Host-only Networks, rede vboxnet0 (se a lista Nome estiver vazia, clique em Criar). Em Adaptador: IPv4 192.168.0.1 e máscara 255.255.255.0. Em Servidor DHCP: habilitado, entregando IPs de 192.168.0.101 a 192.168.0.254.

Antes de começar

Prepare as duas máquinas

Você vai usar duas máquinas, as duas com Linux Mint: a máquina virtual (servidor) e a máquina real (cliente). Faça isto depois do Passo 0, com a VM já ligada.

Terminal da VM

Na VM, aperte Ctrl + Alt + T. Use a mesma janela até o fim da atividade.

Senha do sudo

Quando pedir senha, digite a sua. Ela não aparece na tela, é normal.

PuTTY na máquina real

O PuTTY já deve estar instalado na máquina real. Ele é o programa que vai se conectar à VM pela porta 22.

Conceito

O que é o SSH

Conheça o serviço antes de instalar.

O que é

O SSH (Secure Shell) é um protocolo para controlar outro computador pela rede usando o terminal. No Linux, o programa mais usado é o OpenSSH.

Para que serve

O servidor fica esperando conexões na porta 22. Quem conecta recebe um terminal da máquina remota, como se estivesse sentado na frente dela.

Vantagens

  • Tudo é criptografado, até a senha
  • Administra servidores sem monitor
  • Aceita login por chaves, mais seguro
  • Copia arquivos com scp e sftp
  • Gratuito e já vem em quase todo Linux

Passo 01 · VM

Instalar o SSH

O Linux Mint já vem com o cliente SSH. Falta instalar o servidor, que recebe as conexões.

  1. 1

    Atualize e instale

    terminal
    sudo apt update
sudo apt install -y openssh-server

    O pacote openssh-server cria o serviço ssh, gera as chaves do servidor em /etc/ssh/ e abre a porta 22.

Passo 02 · VM

Verificar se o serviço está ativo

Confira o estado do serviço, veja se a porta 22 está aberta e faça um teste dentro da própria VM.

  1. 1

    Ligue o serviço

    Ligue o SSH e deixe ele iniciar junto com o sistema.

    terminal
    sudo systemctl enable --now ssh
  2. 2

    Veja o status

    Procure active (running) em verde. Aperte q para sair.

    terminal
    systemctl status ssh
    saída esperada
    ● ssh.service - OpenBSD Secure Shell server
     Loaded: loaded (/usr/lib/systemd/system/ssh.service; enabled)
     Active: active (running)
TriggeredBy: ● ssh.socket

    A linha TriggeredBy: ssh.socket é normal no Linux Mint 22. Ela indica que o sistema liga o SSH sozinho quando chega uma conexão.

  3. 3

    Pare, inicie e reinicie

    Rode o systemctl is-active ssh depois de cada comando e compare.

    terminal
    sudo systemctl stop ssh.socket ssh
systemctl is-active ssh     # inactive
sudo systemctl start ssh
systemctl is-active ssh     # active
sudo systemctl restart ssh
systemctl is-active ssh     # active
  4. 4

    Confira a porta 22

    O comando ss lista as portas abertas. Deve aparecer LISTEN na linha com :22.

    terminal
    sudo ss -tlnp | grep :22
    saída esperada
    LISTEN 0  4096  0.0.0.0:22  0.0.0.0:*  users:(("sshd",...))
  5. 5

    Ative o firewall e libere o SSH

    Ative o firewall, confira o status e libere o SSH. Depois rode o status de novo: deve aparecer 22/tcp ALLOW.

    terminal
    sudo ufw enable
sudo ufw status         # Status: active
sudo ufw allow ssh      # libera a porta 22
sudo ufw status         # 22/tcp ALLOW
  6. 6

    Teste dentro da própria VM

    Na primeira vez, digite yes para aceitar a impressão digital, depois a sua senha. Saia com exit.

    terminal
    ssh localhost
exit
Passo 03 · VM

Verificar o IP da máquina virtual

O IP é o endereço que você vai digitar no PuTTY. Ele vem da rede Somente Hospedeiro que você configurou no Passo 0.

  1. 1

    Mostre o IP da VM

    Anote o número que começa com 192.168.0., por exemplo 192.168.0.101. Se aparecer só 10.0.2.15, a VM está apenas em NAT: desligue e refaça o Passo 0.

    terminal
    hostname -I
  2. 2

    Veja os detalhes da placa de rede

    O IP aparece depois de inet.

    terminal
    ip -4 addr show
    saída esperada
    2: enp0s3: <BROADCAST,MULTICAST,UP,LOWER_UP> ...
    inet 192.168.0.101/24 brd 192.168.0.255 scope global dynamic enp0s3
  3. 3

    Anote o seu usuário

    Ele será pedido no PuTTY.

    terminal
    whoami
  4. 4

    Teste a rede pela máquina real Máquina real

    Abra o terminal da máquina real e teste se a VM responde (troque pelo seu IP).

    terminal da máquina real
    ping -c 4 192.168.0.101
Passo 04 · Máquina real

Acessar a VM pelo PuTTY

O PuTTY é o cliente SSH instalado no Linux Mint da máquina real. Com ele você abre um terminal da VM.

  1. 1

    Aceite a impressão digital

    Clique em Open. Na primeira conexão aparece o PuTTY Security Alert com a impressão digital do servidor. Clique em Accept.

  2. 2

    Faça o login

    Em login as:, digite o usuário da VM. Depois digite a senha (ela não aparece).

  3. 3

    Confirme que está dentro da VM

    janela do PuTTY
    whoami          # seu usuário na VM
hostname        # nome da VM
who             # mostra a conexão pts/0 vinda do IP da máquina real
uname -a        # sistema da VM
exit            # fecha a conexão
  4. 4

    Veja o login no log VM

    Procure Accepted password com o IP da máquina real.

    terminal
    sudo grep sshd /var/log/auth.log | tail -n 5

Feche o PuTTY sempre com exit. Assim a conexão é encerrada do jeito certo e os comandos ficam gravados no histórico da VM.

Desafio 05 · VM e máquina real

Autenticação por chaves no SSH

Crie um par de chaves na VM, autorize a chave pública e use a chave privada no PuTTY para entrar sem digitar a senha do usuário.

Chave pública .pub

Funciona como um cadeado. Fica no servidor, dentro de ~/.ssh/authorized_keys. Pode ser mostrada para qualquer um.

Chave privada

Funciona como a chave do cadeado. Fica só com você, no PuTTY em formato .ppk. Nunca envie para ninguém.

Parte A · Criar e autorizar as chaves na VM

  1. 1

    Crie o par de chaves VM

    Aperte Enter para aceitar o local padrão. Escolha uma frase-senha (passphrase) e repita.

    terminal
    ssh-keygen -t ed25519 -C "aluno@ifsc"
    saída esperada
    Your identification has been saved in /home/aluno/.ssh/id_ed25519
Your public key has been saved in /home/aluno/.ssh/id_ed25519.pub
  2. 2

    Veja os arquivos criados VM

    terminal
    ls -l ~/.ssh
cat ~/.ssh/id_ed25519.pub
  3. 3

    Autorize a chave pública VM

    Ajuste também as permissões. O SSH recusa a chave se a pasta estiver aberta para outros usuários.

    terminal
    cat ~/.ssh/id_ed25519.pub >> ~/.ssh/authorized_keys
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
  4. 4

    Converta para o formato do PuTTY VM

    O PuTTY usa chaves .ppk. Será pedida a frase-senha.

    terminal
    sudo apt install -y putty-tools
puttygen ~/.ssh/id_ed25519 -o ~/aluno.ppk
ls -l ~/aluno.ppk

Parte B · Trazer a chave para a máquina real

O que é o scp

O scp (secure copy) copia arquivos de um computador para outro pela rede. Funciona como o cp, mas a origem ou o destino pode estar em outra máquina. Já vem no Linux Mint e não precisa de root.

Como ele copia

Ele usa a mesma conexão do SSH: porta 22, tudo criptografado. Pede o usuário e a senha da VM, envia o arquivo e fecha a conexão. Por isso o SSH da VM precisa estar ativo.

Como ler o comando scp ORIGEM DESTINO

scp aluno@192.168.0.101:/home/aluno/aluno.ppk .

  1. 5

    Copie a chave com o scp Máquina real

    Troque aluno pelo seu usuário da VM e o IP pelo da VM. Digite a senha do usuário da VM. O arquivo aluno.ppk vai para a Pasta Pessoal da máquina real.

    terminal da máquina real
    cd ~
scp aluno@192.168.0.101:/home/aluno/aluno.ppk .
chmod 600 ~/aluno.ppk
ls -l ~/aluno.ppk
  2. 6

    Apague a cópia que ficou na VM VM

    terminal
    rm ~/aluno.ppk

Parte C · Incluir a chave no PuTTY

  1. 7

    Abra a sessão salva Máquina real

    Abra o PuTTY, clique em VM-Mint e em Load.

  2. 8

    Escolha a chave Máquina real

    Vá em Connection › SSH › Auth (nas versões mais novas do PuTTY, Auth › Credentials). Em Private key file for authentication, clique em Browse... e escolha aluno.ppk.

  3. 9

    Preencha o usuário Máquina real

    Em Connection › Data, preencha Auto-login username com o seu usuário da VM.

  4. 10

    Salve e conecte Máquina real

    Volte em Session, selecione VM-Mint e clique em Save. Depois clique em Open. O PuTTY mostra Authenticating with public key "aluno@ifsc" e pede a frase-senha da chave, não a senha do usuário.

  5. 11

    Prove que entrou por chave PuTTY

    Agora o log deve mostrar Accepted publickey.

    janela do PuTTY
    sudo grep "Accepted publickey" /var/log/auth.log | tail -n 3
exit
Ajuda

Se não funcionar

Mensagens mais comuns e o que fazer.

Connection timed out

IP errado ou rede da VM fora do Somente Hospedeiro. Confira o hostname -I e refaça o Passo 0.

Connection refused

Serviço SSH parado. Rode sudo systemctl enable --now ssh.

Access denied

Usuário ou senha errados. Use o nome que aparece no whoami.

Server refused our key

Chave não autorizada ou permissões erradas. Refaça os itens 3 e 4 da Parte A do desafio.

Unable to use key file

O arquivo não está no formato .ppk. Converta com puttygen ~/.ssh/id_ed25519 -o ~/aluno.ppk.

Host key ... has changed

O SSH da VM foi reinstalado. Confirme que é a sua VM e clique em Accept.
