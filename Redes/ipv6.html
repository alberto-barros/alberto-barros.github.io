Conceito

O que é o IPv6?

O IPv6 (Internet Protocol versão 6) é a versão mais nova do protocolo IP. Ele identifica cada dispositivo da rede com um endereço de 128 bits e foi criado para substituir o IPv4, que ficou pequeno demais para a Internet.

O endereço IPv4 tem 32 bits e permite cerca de 4,3 bilhões de endereços. O IPv6 usa 128 bits, o que dá 2128 endereços. O número exato é 340.282.366.920.938.463.463.374.607.431.768.211.456. Lê-se: trezentos e quarenta undecilhões. É tanto espaço que cada pessoa, cada celular e cada lâmpada inteligente pode ter endereços públicos próprios (DEERING; HINDEN, 2017).

O endereço é escrito em hexadecimal, em 8 grupos de 16 bits separados por dois-pontos. Exemplo: 2001:0db8:acad:0001:0000:0000:0000:0010. Cada grupo tem de 1 a 4 dígitos hexadecimais (0 a 9 e a a f) (HINDEN; DEERING, 2006).

Como no IPv4, o endereço tem uma parte de rede e uma parte de host. No IPv6 a divisão é indicada pelo comprimento do prefixo, escrito depois da barra (/64). Não existe máscara em decimal: só o prefixo (KUROSE; ROSS, 2013).

Vantagens

Por que migrar para o IPv6

O IPv6 não nasceu só para ter mais endereços. O protocolo foi redesenhado para deixar a rede mais simples de configurar e mais eficiente para os roteadores (TANENBAUM; WETHERALL, 2011).

Espaço de endereços enorme

Com 128 bits acabou a escassez. Cada rede recebe sub-redes /64 inteiras, sem precisar economizar endereço.

Conexão fim a fim sem NAT

Todo dispositivo pode ter endereço público. O NAT, criado para poupar endereços IPv4, deixa de ser necessário. Isso simplifica jogos, VoIP e acesso remoto.

Cabeçalho mais simples

O cabeçalho tem tamanho fixo de 40 bytes e não tem checksum. Os roteadores processam menos campos por pacote (DEERING; HINDEN, 2017).

Autoconfiguração (SLAAC)

O host monta o próprio endereço a partir do prefixo anunciado pelo roteador, sem servidor DHCP (THOMSON; NARTEN; JINMEI, 2007).

Segurança prevista no projeto

O IPv6 foi desenhado com suporte ao IPsec. O NAT nunca foi um firewall: continue usando filtros de tráfego também no IPv6.

Multicast no lugar do broadcast

Não existe broadcast. O ARP foi trocado pelo NDP, que usa multicast e só incomoda os dispositivos interessados (NARTEN et al., 2007).

Camada 3 · Rede

O cabeçalho do pacote IPv6

Assim como o IPv4, o IPv6 trabalha na camada 3 (Rede) do modelo OSI e entrega o dado em forma de pacote. O cabeçalho ficou menor e mais regular: são só 8 campos, todos em posição fixa (DEERING; HINDEN, 2017).

Os campos de controle usam 32 bits por linha. Cada endereço IPv6 tem 128 bits e foi desenhado em uma linha só.

Hop Limit no lugar do TTL

O campo de limite de saltos faz o papel do TTL do IPv4: cada roteador subtrai 1 e descarta o pacote quando chega a zero.

Próximo cabeçalho

Diz o que vem depois do cabeçalho IPv6: 6 = TCP, 17 = UDP, 58 = ICMPv6. Também encadeia cabeçalhos de extensão opcionais.

Sem checksum e sem fragmentação nos roteadores

A verificação de erros fica nas camadas de enlace e transporte. Só o host de origem fragmenta pacotes, e todo caminho precisa aceitar pelo menos 1280 bytes.

Mesma camada, outro protocolo

O switch continua lendo só o quadro (MAC). O IPv6 vive na camada 3, onde ficam roteadores e o comando ping.

Como endereçar

Como um dispositivo recebe o endereço IPv6

Há três formas de atribuir um endereço a uma interface. O roteador anuncia o prefixo da rede por mensagens Router Advertisement (ICMPv6) e o host decide o resto (THOMSON; NARTEN; JINMEI, 2007).

1 · Manual (estático)

Você digita endereço, prefixo e gateway. É o padrão para roteadores, servidores e para os laboratórios desta aula.

2 · SLAAC

O host junta o prefixo /64 anunciado pelo roteador a um identificador de 64 bits que ele mesmo gera. Não precisa de servidor.

3 · DHCPv6

Um servidor entrega endereço e opções (DNS, domínio). Dá controle e registro de quem usa cada endereço.

Como o SLAAC monta o identificador (EUI-64)

O método clássico parte do endereço MAC (48 bits). Ele divide o MAC ao meio, insere ff:fe no centro e inverte o 7º bit do primeiro byte. O resultado são os 64 bits de interface (HINDEN; DEERING, 2006).

Sistemas atuais costumam preferir um identificador aleatório e estável para não expor o MAC na Internet, mas a lógica de prefixo + interface é a mesma.

Exemplo: MAC 00:1A:2B:3C:4D:5E

1. MAC00:1A:2B : 3C:4D:5E
2. Insere ff:fe00:1A:2B:ff:fe:3C:4D:5E
3. Inverte o bit U/L00 (0000 0000) → 02 (0000 0010)
4. ID da interface021a:2bff:fe3c:4d5e
5. Com prefixo2001:db8:acad:1:21a:2bff:fe3c:4d5e
Link-localfe80::21a:2bff:fe3c:4d5e

Entregando IPv6 automaticamente: o roteador como servidor DHCPv6

Nesta atividade o aluno deixa o PC em modo automático e quem entrega o endereço é o roteador R1, que faz o papel de servidor DHCPv6.

O roteador anuncia na rede uma mensagem de Router Advertisement com o flag M (managed config) ligado. Esse flag diz ao PC: “peça seu endereço a um servidor DHCPv6”. O PC então pergunta ao servidor e recebe um endereço de dentro do prefixo 2001:db8:acad:1::/64, mais o DNS (NARTEN et al., 2007).

Como o servidor guarda quem recebeu cada endereço, esse modo se chama DHCPv6 com estado (stateful). É o equivalente mais próximo do DHCP que você conhece no IPv4.

Sub-redes

Como criar sub-redes IPv6

No IPv4 você empresta bits de host para economizar endereços. No IPv6 sobra espaço, então a sub-rede é uma questão de organização: o provedor entrega um prefixo (em geral /48 ou /56) e você escolhe o ID de cada sub-rede nos bits seguintes, até o /64 (NARTEN; HUSTON; ROBERTS, 2011).

Regra de ouro: toda LAN usa um prefixo /64. O SLAAC e o NDP foram projetados para um identificador de interface de 64 bits.

Por isso os 64 bits finais ficam fixos como parte de host e você só mexe nos bits entre o prefixo recebido e o /64. Esses bits são o ID da sub-rede. Com um /48 sobram 16 bits, ou seja, 216 = 65.536 sub-redes. Com um /56, 8 bits e 256 sub-redes (HINDEN; DEERING, 2006).

Como o ID de sub-rede é hexadecimal, a contagem vai 0, 1, 2 … 9, a, b … f, 10, 11 … e ocupa o 4º grupo do endereço quando o prefixo recebido é /48.

    Dentro de cada /64 o primeiro endereço (::1) costuma ser o gateway. Hosts recebem o resto por SLAAC, DHCPv6 ou de forma manual. Não há endereço de broadcast para reservar, e é comum usar /127 nos links ponto a ponto entre roteadores.

Solução de problemas

Erros comuns

Usar :: duas vezes

2001::db8::1 é ambíguo: não dá para saber quantos grupos zero cada :: substitui. Use :: só uma vez.

Prefixo diferente de /64 na LAN

Redes com SLAAC precisam de /64. Um prefixo como /80 numa LAN quebra a autoconfiguração.

Esquecer o ipv6 unicast-routing

Sem esse comando o roteador Cisco tem endereço IPv6, mas não encaminha pacotes entre as sub-redes.

Tratar o ID da sub-rede como decimal

O ID é hexadecimal: depois de 9 vem a, e depois de f vem 10. A sub-rede :10:: é a 17ª, não a 10ª.

Pingar link-local sem a interface

No Linux, ping -6 fe80::1 falha porque há um fe80::/10 em cada interface. Informe a placa: fe80::1%enp0s3.

“Ping não responde” no laboratório real

O firewall do Windows pode bloquear o ICMPv6. Libere a regra de eco do ICMPv6, pois o NDP também depende dele.

Achar que sem NAT não precisa de firewall

Com endereços públicos em todos os hosts, o filtro de tráfego passa a ser ainda mais importante. Mantenha regras no roteador ou no firewall.

Misturar IPv4 e IPv6 no ping

No Windows e no Linux o ping escolhe a versão pelo endereço. Para forçar, use ping -4 ou ping -6.
