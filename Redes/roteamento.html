Parte 1 · Conceito

O que é roteamento?

Roteamento é o processo de escolher por onde um pacote IP deve seguir para sair de uma rede e chegar a outra. Quem faz essa escolha é o roteador, consultando a sua tabela de roteamento.

O switch entrega quadros dentro de uma rede, olhando o endereço MAC. O roteador liga redes diferentes e trabalha na camada 3, olhando o IP de destino. Cada porta do roteador pertence a uma rede e serve de gateway para ela.

Quando o pacote chega, o roteador procura na tabela a rota que combina com o IP de destino. Se achar, envia o pacote para o próximo salto (o roteador vizinho) ou direto ao destino, se a rede estiver ligada nele. Se não achar, o pacote é descartado e a origem recebe Destination host unreachable.

Nenhum roteador conhece o caminho inteiro. Cada um decide só o próximo salto, e o pacote avança de roteador em roteador até a rede de destino. Por isso todos os roteadores do caminho precisam ter a rota, na ida e na volta.

Parte 1 · Por que usar

Vantagens e benefícios do roteamento

É o roteamento que permite juntar redes pequenas em redes grandes. A própria Internet é um conjunto de redes ligadas por roteadores.

Liga redes diferentes

PCs em redes IP distintas, em salas, câmpus ou cidades diferentes, passam a se comunicar pelo roteador.

Caminhos redundantes

Com mais de um caminho, a queda de um enlace não derruba a rede: o tráfego segue pelo outro lado.

Melhor caminho

O roteador compara as rotas pela métrica e usa a melhor. Com custos iguais, pode dividir o tráfego entre elas.

Contém o broadcast

O broadcast de uma rede não atravessa o roteador. Cada rede fica com o seu próprio tráfego de ARP e DHCP.

Controle e segurança

Todo tráfego entre redes passa pelo roteador. É nele que se aplicam filtros (ACLs) e se registra quem fala com quem.

Escala

A tabela guarda uma linha por rede, não por computador. Uma rota pode representar milhares de hosts.

Parte 1 · Tipos de rota

Roteamento estático × dinâmico

A tabela de roteamento pode ser preenchida de duas formas: pelo administrador, linha por linha, ou pelos próprios roteadores, conversando entre si com um protocolo de roteamento.

Estático

O administrador digita cada rota com o comando ip route. A rota fica na tabela até alguém apagar.

  • Simples e previsível: o caminho é sempre o que foi digitado.
  • Leve: não gasta CPU nem banda com mensagens entre roteadores.
  • Não se adapta: se um enlace cai, a rota não muda sozinha, mesmo existindo outro caminho.
  • Trabalhoso: cada rede nova exige mexer em vários roteadores.

Indicado para redes pequenas, redes com uma única saída e para a rota padrão (0.0.0.0 0.0.0.0).

Dinâmico

Os roteadores anunciam as redes que conhecem aos vizinhos e montam a tabela sozinhos.

  • Aprende sozinho: basta dizer quais redes cada roteador anuncia.
  • Adapta-se: se um enlace cai, os roteadores recalculam e usam outro caminho.
  • Escala melhor: uma rede nova é anunciada para todos automaticamente.
  • Custa mais: usa CPU, memória e banda, e leva um tempo para convergir.

Indicado para redes médias e grandes e sempre que houver caminhos redundantes.

A distância administrativa mede a confiança na origem da rota: conectada = 0, estática = 1, RIP = 120. Se o roteador conhece duas rotas para a mesma rede, entra na tabela a de menor distância. Por isso uma rota estática sempre vence uma rota RIP para o mesmo destino.

        Parte 3 · Desafio · Roteamento dinâmico
        
Troque as rotas estáticas por RIP

        
Seu desafio: apagar as rotas estáticas dos 4 roteadores, ativar o RIP versão 2 e provar, com testes, que o pacote muda de caminho sozinho quando um enlace cai e que o site cisco.com.br continua abrindo.

      

    


    

      

        
O RIP (Routing Information Protocol) é um protocolo de vetor de distância: cada roteador conta aos vizinhos quais redes conhece e a quantos saltos elas estão.

        
A cada 30 segundos o roteador envia a sua tabela aos vizinhos. Quem recebe soma 1 salto e guarda a rota se ela for nova ou melhor que a que já tinha. Depois de algumas trocas, todos conhecem todas as redes: a rede convergiu.

        
A métrica é a contagem de saltos, e o melhor caminho é o que passa por menos roteadores. O limite é 15; uma rede a 16 saltos é considerada inalcançável. Quando um enlace cai, o roteador avisa os vizinhos e todos recalculam.

        
Use sempre a versão 2: ela envia a máscara junto com a rede, o que é obrigatório aqui porque os enlaces usam /30. O comando no auto-summary impede o RIP de resumir tudo em 10.0.0.0/8.

      Solução de problemas
      
Erros comuns

      
Antes de pedir ajuda, confira estes casos. Os comandos que mais ajudam no roteador são show ip interface brief e show ip route; no PC, o ipconfig.

    

    
Parte 1 · Interfaces e rotas estáticas

    

      
Link vermelho
Faltou no shutdown em uma das pontas, ou o cabo não é Cross-Over. Rode show ip interface brief: a porta deve estar up/up, não administratively down.

      
“Destination host unreachable”
Quem responde é um roteador avisando que não tem rota para o destino. Veja o IP de quem respondeu e confira o show ip route desse roteador.

      
“Request timed out”
O pacote foi, mas a resposta não voltou. Normalmente falta a rota de volta em algum roteador do caminho, ou o gateway do PC de destino está errado.

      
“% Invalid next hop address”
O próximo salto digitado é um IP do próprio roteador. O próximo salto é sempre o IP do vizinho, na outra ponta do cabo.

      
“% overlaps with GigabitEthernet”
Duas portas do mesmo roteador receberam IPs da mesma rede. Confira a tabela do passo 2: cada porta fica em uma rede diferente.

      
Rota S não aparece no show ip route
A rota estática só entra na tabela se o próximo salto for alcançável. Confira se a porta que leva a ele está up/up e se o IP foi digitado certo.

      
Ping ao próprio gateway falha
IP, máscara ou gateway do PC estão errados, ou o PC foi ligado em outra porta que não a G0/0.

      
Configuração sumiu ao reabrir
Faltou copy running-config startup-config em cada roteador ou salvar o arquivo .pkt (Ctrl+S) antes de fechar.

    

    
Parte 2 · Servidor web e DNS

    

      
“Host Name Unresolved”
O PC não conseguiu traduzir o nome. Confira o campo DNS Server do PC, se o DNS Service está em On e se o nome do registro é exatamente cisco.com.br.

      
“Request Timeout” no navegador
O nome foi resolvido, mas a página não veio. Teste ping 192.168.3.100: se falhar, o problema é de roteamento ou o gateway do servidor; se responder, veja se o HTTP está em On.

      
Abre pelo IP, mas não pelo nome
O roteamento e o HTTP estão certos; o defeito é só no DNS. Rode nslookup cisco.com.br no PC e veja qual servidor responde.

      
PC2 ou servidor sem comunicação
Entre o R3 e o switch o cabo é Straight-Through. Confira também se o PC2 e o SRV-WEB estão na rede 192.168.3.0/24 com gateway 192.168.3.1.

    

    
Parte 3 · Desafio RIP

    

      
Nenhuma rota R na tabela
Faltou o network 10.0.0.0 (sem ele o RIP não fala pelos enlaces), o vizinho ainda não foi configurado, ou não passaram 30 s. Confira com show ip protocols.

      
Continua aparecendo S em vez de R
Sobrou rota estática. Ela tem distância 1 e vence o RIP (120). Apague com no ip route … e olhe a tabela de novo.

      
Aparece 10.0.0.0/8 em vez das redes /30
Faltou version 2 ou no auto-summary em algum roteador. Corrija nos 4 e aguarde uma nova atualização.

      
Vizinhos não trocam rotas
O passive-interface foi aplicado na porta errada. Só a G0/0 é passiva; G0/1 e G0/2 precisam enviar anúncios.
