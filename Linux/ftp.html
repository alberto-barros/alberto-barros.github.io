Antes de começar

Prepare as duas máquinas

Nesta aula você usa a máquina virtual (servidor) e a máquina hospedeira (cliente) ao mesmo tempo.

Apache funcionando

A VM precisa ter o Apache instalado da aula anterior, com uma página em /var/www/html. Teste com curl -I http://localhost.

Rede somente hospedeiro

No VirtualBox, ligue um adaptador da VM em Placa de rede exclusiva de hospedeiro (host-only). Assim a hospedeira e a VM conversam numa rede só delas, em geral 192.168.56.0/24. Deixe outro adaptador em NAT para a VM ter internet e instalar pacotes.

FileZilla na hospedeira

O FileZilla Client deve estar instalado na máquina hospedeira. Ele é o programa que vai se conectar ao servidor.

Abra o terminal da VM com Ctrl + Alt + T. Quando pedir senha, digite a sua. Ela não aparece na tela, é normal.

Conceito

O que é FTP

Entenda o protocolo antes de instalar o servidor.

O que é

FTP (File Transfer Protocol) é o protocolo de transferência de arquivos. Ele existe desde 1971 e funciona no modelo cliente e servidor: o servidor guarda os arquivos e o cliente se conecta para enviar ou baixar.

Para que serve

  • Publicar sites: enviar HTML, CSS e imagens para o servidor web
  • Fazer backup de arquivos do servidor
  • Trocar arquivos grandes entre computadores
  • Atualizar sites em hospedagens

Vantagens

  • Gratuito e aceito em quase todo sistema
  • Transfere pastas inteiras de uma vez
  • Retoma transferências interrompidas
  • Clientes fáceis de usar, como o FileZilla
  • Controle de acesso por usuário e senha

Portas usadas

21ControlePorta onde o servidor espera a conexão. Por ela passam o login e os comandos (listar, enviar, baixar).
20Dados (modo ativo)No modo ativo, o servidor abre a conexão de dados a partir desta porta até o cliente.
>1023Dados (modo passivo)No modo passivo, o padrão do FileZilla, o servidor abre uma porta alta e o cliente se conecta nela.
22SFTPTransferência de arquivos segura pelo SSH. Tudo vai criptografado, inclusive a senha.

Cuidados

A senha viaja sem criptografia

No FTP comum, o usuário, a senha e os arquivos passam pela rede em texto puro. Quem capturar o tráfego (Wireshark, por exemplo) consegue ler tudo. Na internet, prefira SFTP (porta 22) ou FTPS (FTP com TLS).

Desative o acesso anônimo

Com anonymous_enable=YES, qualquer pessoa entra sem senha. Deixe sempre NO, a não ser que o servidor seja de downloads públicos.

Limite as pastas

Sem restrição, o usuário navega por todo o sistema de arquivos. Em produção use chroot_local_user=YES para prender cada usuário na própria pasta.

Senhas fortes e firewall

Robôs tentam senhas na porta 21 o tempo todo. Use senhas fortes, nunca libere o usuário root e abra no firewall só as portas necessárias.

Passo 01 · VM

Instalar o servidor FTP

Vamos usar o vsftpd (Very Secure FTP Daemon), o servidor FTP mais usado no Linux.

  1. 1

    Atualize e instale

    terminal
    sudo apt update
sudo apt install -y vsftpd
  2. 2

    Veja o status

    Procure active (running) em verde. Aperte q para sair.

    terminal
    systemctl status vsftpd
  3. 3

    Confira a porta 21

    O comando ss lista as portas abertas. A linha com :21 mostra que o servidor está esperando conexões.

    terminal
    sudo ss -tlnp | grep :21
    saída esperada
    LISTEN 0  32  *:21  *:*  users:(("vsftpd",pid=2154,fd=3))
Passo 02 · VM

Configurar o vsftpd

Por padrão o vsftpd só deixa baixar arquivos. Vamos liberar o envio para poder trocar a página do site.

  1. 1

    Guarde a configuração original

    terminal
    sudo cp /etc/vsftpd.conf /etc/vsftpd.conf.original
  2. 2

    Abra o arquivo de configuração

    terminal
    sudo nano /etc/vsftpd.conf

    Procure cada linha com Ctrl+W. Para ativar uma linha, apague o # do começo. Deixe assim:

    LinhaO que faz
    listen=NOJá vem assim. O servidor atende IPv4 e IPv6 pela linha de baixo
    listen_ipv6=YESJá vem assim
    anonymous_enable=NOBloqueia o acesso sem senha
    local_enable=YESPermite entrar com os usuários do Linux
    write_enable=YESTire o #. Libera enviar, apagar e renomear arquivos
    local_umask=022Tire o #. Arquivos enviados ficam com permissão 644, que o Apache consegue ler
    xferlog_enable=YESJá vem assim. Registra as transferências no log
  3. 3

    Defina a pasta inicial

    Vá até o fim do arquivo com Ctrl+End e cole estas linhas. A local_root faz o FTP abrir direto na pasta do site, /var/www/html, em vez da pasta pessoal do usuário.

    final do /etc/vsftpd.conf
    # pasta onde o FTP abre depois do login
local_root=/var/www/html

    Salve com Ctrl+O e Enter. Saia com Ctrl+X.

  4. 4

    Confira e reinicie

    O grep mostra só as linhas ativas. Depois reinicie para valer a nova configuração.

    terminal
    grep -v '^#' /etc/vsftpd.conf | grep -v '^$'
sudo systemctl restart vsftpd
systemctl is-active vsftpd     # active
  5. 5

    Firewall, se estiver ligado

    No Linux Mint o firewall (ufw) vem desligado. Se o seu disser Status: active, desabilite o firewall para a aula.

    terminal
    sudo ufw status
sudo ufw disable
sudo ufw status     # Status: inactive

    Com o firewall desabilitado, o FileZilla consegue usar a porta 21 e as portas de dados sem bloqueio.

Passo 03 · VM

Dar permissão na pasta do site

A pasta /var/www/html pertence ao root. Pelo FTP você entra com o seu usuário, então ele precisa ser o dono da pasta para conseguir gravar.

  1. 1

    Veja quem é o dono hoje

    terminal
    ls -ld /var/www/html
ls -l /var/www/html
    saída esperada
    drwxr-xr-x 2 root root 4096 nov  9 10:12 /var/www/html
  2. 2

    Passe a pasta para o seu usuário

    A variável $USER já tem o seu nome de usuário. O Apache continua lendo os arquivos normalmente.

    terminal
    sudo chown -R $USER:$USER /var/www/html
  3. 3

    Confira

    Agora aparece o seu usuário no lugar de root.

    terminal
    ls -l /var/www/html
    saída esperada
    -rw-r--r-- 1 aluno aluno  242 nov  9 10:15 index.html
-rw-r--r-- 1 aluno aluno 10671 nov  9 10:12 index.html.original
Passo 04 · VM

Descobrir o IP e testar

O FileZilla precisa do IP da VM. Antes de ir para a hospedeira, teste o login no próprio servidor.

  1. 1

    Descubra o IP da VM

    Anote o IP que começa com 192.168.56, por exemplo 192.168.56.101. O outro IP (10.0.2.15) é o do NAT e não serve para o FileZilla. Anote também o seu usuário.

    terminal
    hostname -I
whoami
  2. 2

    Teste o login FTP no próprio servidor

    O curl também fala FTP. Digite a sua senha quando pedir. Se aparecer a lista de arquivos do site, o login funciona e o FTP já abriu em /var/www/html.

    terminal
    curl -u $USER ftp://localhost/
    saída esperada
    Enter host password for user 'aluno':
-rw-r--r--    1 1000     1000          242 Nov 09 10:15 index.html
-rw-r--r--    1 1000     1000        10671 Nov 09 10:12 index.html.original
  3. 3

    Teste a rede pela hospedeira

    Na máquina hospedeira, abra o Prompt de Comando e rode ping 192.168.56.101 com o IP da sua VM. Se aparecer Resposta de…, as duas máquinas se enxergam.

Erros comuns

    

      
530 Login incorrect
Usuário ou senha errados. Use o resultado do whoami e a senha do Linux Mint, não a da hospedeira.

      
553 Could not create file
Sem permissão para gravar. Confira se write_enable=YES está sem # e refaça o Passo 3 (chown).

      
Tempo limite de conexão
A hospedeira não alcança a VM. Confira o IP, se um adaptador da VM está em Placa de rede exclusiva de hospedeiro e se o firewall libera a porta 21.

      
Falha ao listar o diretório
O login funciona mas a lista não aparece. O firewall da VM está bloqueando as portas de dados. Confira com sudo ufw status e, no laboratório, desligue com sudo ufw disable.

        Desafio · VM e hospedeira
        
Deixar o vsftpd seguro com TLS

        
Hoje a sua senha passa pela rede em texto puro. Neste desafio você cria uma chave e um certificado e obriga o vsftpd a criptografar tudo. Esse modo se chama FTPS (FTP sobre TLS) e continua usando a porta 21.

      

    


    

      
Chave privada
Arquivo vsftpd.key. Fica só no servidor e só o root pode ler. É ela que prova que o servidor é ele mesmo.

      
Certificado
Arquivo vsftpd.pem. É público e vai para o FileZilla na hora da conexão. Como nós mesmos assinamos, ele é autoassinado.

    


    
    
      
  1. 
        
    1
    
        
    
          
    Crie a chave e o certificado VM
    
          
    O openssl gera uma chave RSA de 2048 bits e um certificado válido por 365 dias. Troque o IP no final pelo IP da sua VM.
    terminal
    sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /etc/ssl/private/vsftpd.key \
  -out /etc/ssl/certs/vsftpd.pem \
  -subj "/C=BR/ST=Santa Catarina/L=Garopaba/O=IFSC/CN=192.168.56.101"
    
          
    OpçãoO que faz
    -x509Cria um certificado em vez de um pedido de certificado
    -nodesNão coloca senha na chave, para o vsftpd iniciar sozinho
    -days 365O certificado vale por um ano
    -newkey rsa:2048Cria uma chave RSA nova de 2048 bits
    -subjDados do certificado: país, estado, cidade, instituição e o IP do servidor (CN)
