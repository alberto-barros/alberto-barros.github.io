Antes de começar

Prepare as duas máquinas

Nesta aula você usa a máquina virtual (servidor) e a máquina hospedeira (cliente) ao mesmo tempo.

Apache funcionando

A VM precisa ter o Apache instalado da aula anterior, com uma página em /var/www/html. Teste com curl -I http://localhost.

Rede somente hospedeiro

No VirtualBox, ligue um adaptador da VM em Placa de rede exclusiva de hospedeiro (host-only). Assim a hospedeira e a VM conversam numa rede só delas, em geral 192.168.56.0/24. Deixe outro adaptador em NAT para a VM ter internet e instalar pacotes.

FileZilla na hospedeira

O FileZilla Client deve estar instalado na máquina hospedeira. Ele é o programa que vai se conectar ao servidor.

Abra o terminal da VM com Ctrl + Alt + T. Quando pedir senha, digite a sua. Ela não aparece na tela, é normal.

Parte 1 · Conceito

O que é FTP

Entenda o protocolo antes de instalar o servidor.

FTP (File Transfer Protocol) é o protocolo de transferência de arquivos entre dois computadores ligados em rede (POSTEL; REYNOLDS, 1985).

Ele existe desde 1971 (BHUSHAN, 1971) e funciona no modelo cliente e servidor: o servidor guarda os arquivos e fica esperando conexões; o cliente se conecta, faz o login e envia ou baixa arquivos (KUROSE; ROSS, 2013).

O FTP usa duas conexões: uma de controle, na porta 21, para o login e os comandos, e outra de dados, aberta só enquanto o arquivo é transferido. Nesta aula o servidor é o vsftpd, na VM, e o cliente é o FileZilla, na máquina hospedeira.

Acessousuário e senha de uma conta do Linux
Parte 1 · Uso

Para que serve o FTP

Sempre que for preciso levar arquivos de um computador para outro, ou deixar um site no ar.

O FTP serve para enviar arquivos ao servidor e baixar arquivos dele, em pastas inteiras e de qualquer tamanho.

É o jeito clássico de publicar um site: o aluno edita a página na própria máquina e envia ao servidor web, que fica na pasta /var/www/html. É o que você vai fazer nesta aula.

Usos mais comuns do FTP

Publicar sitesenviar HTML, CSS e imagens para o servidor web
Fazer backupcopiar os arquivos do servidor para a hospedeira
Trocar arquivos grandesmover arquivos entre computadores da mesma rede
Atualizar sitesmandar a nova versão de uma página em hospedagens
Parte 1 · Por que usar

Vantagens e benefícios do FTP

Por ser simples e antigo, o FTP continua presente em servidores, hospedagens e laboratórios (KUROSE; ROSS, 2013).

Aceito em todo lugar

Praticamente todo sistema operacional e toda hospedagem têm cliente e servidor FTP.

Gratuito

O vsftpd e o FileZilla são gratuitos e de código aberto, sem licença para pagar.

Pastas inteiras

Transfere uma pasta com todos os arquivos de uma vez, mantendo a estrutura.

Retoma transferências

Se a conexão cai no meio de um arquivo grande, a transferência pode continuar de onde parou.

Clientes fáceis

No FileZilla basta arrastar os arquivos de um lado para o outro, sem decorar comandos.

Controle de acesso

Cada pessoa entra com o seu usuário e senha, e o servidor decide o que ela pode fazer.

Parte 1 · Na prática

Portas, cuidados e funcionamento

O que precisa estar aberto, o que pode dar errado e como as duas máquinas vão conversar nesta aula.

Portas usadas

21ControlePorta onde o servidor espera a conexão. Por ela passam o login e os comandos (listar, enviar, baixar) (POSTEL; REYNOLDS, 1985).
20Dados (modo ativo)No modo ativo, o servidor abre a conexão de dados a partir desta porta até o cliente.
>1023Dados (modo passivo)No modo passivo, o padrão do FileZilla, o servidor abre uma porta alta e o cliente se conecta nela (POSTEL; REYNOLDS, 1985).
22SFTPTransferência de arquivos segura pelo SSH. Tudo vai criptografado, inclusive a senha.

Cuidados

A senha viaja sem criptografia

No FTP comum, o usuário, a senha e os arquivos passam pela rede em texto puro. Quem capturar o tráfego (Wireshark, por exemplo) consegue ler tudo. Na internet, prefira SFTP (porta 22) ou FTPS (FTP com TLS) (ALLMAN; OSTERMANN, 1999).

Desative o acesso anônimo

Com anonymous_enable=YES, qualquer pessoa entra sem senha. Deixe sempre NO, a não ser que o servidor seja de downloads públicos.

Limite as pastas

Sem restrição, o usuário navega por todo o sistema de arquivos. Em produção use chroot_local_user=YES para prender cada usuário na própria pasta.

Senhas fortes e firewall

Robôs tentam senhas na porta 21 o tempo todo. Use senhas fortes, nunca libere o usuário root e abra no firewall só as portas necessárias.

Passo 01 · VM

Instalar o servidor FTP

Vamos usar o vsftpd (Very Secure FTP Daemon), o servidor FTP mais usado no Linux.

  1. 1

    Atualize e instale

    terminal
    sudo apt update
sudo apt install -y vsftpd
  2. 2

    Veja o status

    Procure active (running) em verde. Aperte q para sair.

    terminal
    systemctl status vsftpd
  3. 3

    Confira a porta 21

    O comando ss lista as portas abertas. A linha com :21 mostra que o servidor está esperando conexões.

    terminal
    sudo ss -tlnp | grep :21
    saída esperada
    LISTEN 0  32  *:21  *:*  users:(("vsftpd",pid=2154,fd=3))
Passo 02 · VM

Configurar o vsftpd

Por padrão o vsftpd só deixa baixar arquivos. Vamos liberar o envio para poder trocar a página do site.

  1. 1

    Guarde a configuração original

    terminal
    sudo cp /etc/vsftpd.conf /etc/vsftpd.conf.original
  2. 2

    Abra o arquivo de configuração

    terminal
    sudo nano /etc/vsftpd.conf

    Procure cada linha com Ctrl+W. Para ativar uma linha, apague o # do começo. Deixe assim: As opções estão descritas no manual do vsftpd (EVANS, [s.d.]).

    LinhaO que faz
    listen=NOJá vem assim. O servidor atende IPv4 e IPv6 pela linha de baixo
    listen_ipv6=YESJá vem assim
    anonymous_enable=NOBloqueia o acesso sem senha
    local_enable=YESPermite entrar com os usuários do Linux
    write_enable=YESTire o #. Libera enviar, apagar e renomear arquivos
    local_umask=022Tire o #. Arquivos enviados ficam com permissão 644, que o Apache consegue ler
    xferlog_enable=YESJá vem assim. Registra as transferências no log
  3. 3

    Defina a pasta inicial

    Vá até o fim do arquivo com Ctrl+End e cole estas linhas. A local_root faz o FTP abrir direto na pasta do site, /var/www/html, em vez da pasta pessoal do usuário.

    final do /etc/vsftpd.conf
    # pasta onde o FTP abre depois do login
local_root=/var/www/html

    Salve com Ctrl+O e Enter. Saia com Ctrl+X.

  4. 4

    Confira e reinicie

    O grep mostra só as linhas ativas. Depois reinicie para valer a nova configuração.

    terminal
    grep -v '^#' /etc/vsftpd.conf | grep -v '^$'
sudo systemctl restart vsftpd
systemctl is-active vsftpd     # active
  5. 5

    Firewall, se estiver ligado

    No Linux Mint o firewall (ufw) vem desligado. Se o seu disser Status: active, desabilite o firewall para a aula.

    terminal
    sudo ufw status
sudo ufw disable
sudo ufw status     # Status: inactive

    Com o firewall desabilitado, o FileZilla consegue usar a porta 21 e as portas de dados sem bloqueio.

Passo 03 · VM

Dar permissão na pasta do site

A pasta /var/www/html pertence ao root. Pelo FTP você entra com o seu usuário, então ele precisa ser o dono da pasta para conseguir gravar.

  1. 1

    Veja quem é o dono hoje

    terminal
    ls -ld /var/www/html
ls -l /var/www/html
    saída esperada
    drwxr-xr-x 2 root root 4096 nov  9 10:12 /var/www/html
  2. 2

    Passe a pasta para o seu usuário

    A variável $USER já tem o seu nome de usuário. O Apache continua lendo os arquivos normalmente.

    terminal
    sudo chown -R $USER:$USER /var/www/html
  3. 3

    Confira

    Agora aparece o seu usuário no lugar de root.

    terminal
    ls -l /var/www/html
    saída esperada
    -rw-r--r-- 1 aluno aluno  242 nov  9 10:15 index.html
-rw-r--r-- 1 aluno aluno 10671 nov  9 10:12 index.html.original
Passo 04 · VM

Descobrir o IP e testar

O FileZilla precisa do IP da VM. Antes de ir para a hospedeira, teste o login no próprio servidor.

  1. 1

    Descubra o IP da VM

    Anote o IP que começa com 192.168.56, por exemplo 192.168.56.101. O outro IP (10.0.2.15) é o do NAT e não serve para o FileZilla. Anote também o seu usuário.

    terminal
    hostname -I
whoami
  2. 2

    Teste o login FTP no próprio servidor

    O curl também fala FTP. Digite a sua senha quando pedir. Se aparecer a lista de arquivos do site, o login funciona e o FTP já abriu em /var/www/html.

    terminal
    curl -u $USER ftp://localhost/
    saída esperada
    Enter host password for user 'aluno':

    Teste a rede pela hospedeira

    Na máquina hospedeira, abra o Prompt de Comando e rode ping 192.168.56.101 com o IP da sua VM. Se aparecer Resposta de…, as duas máquinas se enxergam.

        Desafio · VM e hospedeira · FTPS
        
Deixar o vsftpd seguro com TLS

        
Hoje a sua senha passa pela rede em texto puro. Neste desafio você cria uma chave e um certificado e obriga o vsftpd a criptografar tudo. Esse modo se chama FTPS (FTP sobre TLS) e continua usando a porta 21.

      

    


    

      

        
FTPS é o FTP dentro de uma conexão TLS: a senha e os arquivos viajam criptografados, e o servidor continua na porta 21 (FORD-HUTCHINSON, 2005).

        
Para isso o servidor precisa de dois arquivos. A chave privada (vsftpd.key) fica só no servidor, com leitura apenas para o root, e é ela que prova que o servidor é ele mesmo.

        
O certificado (vsftpd.pem) é público e vai para o FileZilla na hora da conexão. Como nós mesmos assinamos, ele é autoassinado, e por isso o FileZilla pergunta se você confia nele (FORD-HUTCHINSON, 2005).

      

      

        
21Mesma portaO FTPS explícito não muda de porta: começa em texto e passa para TLS.

        
.keyChave privadaSó no servidor, com chmod 600.

        
.pemCertificadoPúblico, vai para o FileZilla confiar.

        
365Dias de validadeChave RSA de 2048 bits.

    Crie a chave e o certificado VM
    
          
    O openssl gera uma chave RSA de 2048 bits e um certificado válido por 365 dias. Troque o IP no final pelo IP da sua VM.
    terminal
    sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /etc/ssl/private/vsftpd.key \

  -subj "/C=BR/ST=Santa Catarina/L=Garopaba/O=IFSC/CN=192.168.56.101"

    -x509Cria um certificado em vez de um pedido de certificado
    -nodesNão coloca senha na chave, para o vsftpd iniciar sozinho

    -newkey rsa:2048Cria uma chave RSA nova de 2048 bits
    -subjDados do certificado: país, estado, cidade, instituição e o IP do servidor (CN)

    Cole a configuração segura VM
    
          
    Vá até o fim do arquivo com Ctrl+End e cole o bloco. Salve com Ctrl+O, Enter e saia com Ctrl+X.
    final do /etc/vsftpd.conf
    # FTPS - FTP seguro com TLS
ssl_enable=YES
rsa_cert_file=/etc/ssl/certs/vsftpd.pem
rsa_private_key_file=/etc/ssl/private/vsftpd.key
allow_anon_ssl=NO
force_local_logins_ssl=YES
force_local_data_ssl=YES
ssl_tlsv1=YES
ssl_sslv2=NO
ssl_sslv3=NO
require_ssl_reuse=NO
ssl_ciphers=HIGH
    
          
    LinhaO que faz
    ssl_enable=YESLiga a criptografia TLS
    rsa_cert_fileOnde está o certificado criado no item 1
    rsa_private_key_fileOnde está a chave privada
    allow_anon_ssl=NONão deixa usuário anônimo usar TLS
    force_local_logins_ssl=YESObriga o login (usuário e senha) a ir criptografado
    force_local_data_ssl=YESObriga os arquivos e as listagens a irem criptografados
    ssl_tlsv1=YES · ssl_sslv2=NO · ssl_sslv3=NOAceita só TLS e recusa os protocolos SSL antigos e quebrados
    require_ssl_reuse=NOEvita erro de conexão de dados com alguns clientes, como o FileZilla
    ssl_ciphers=HIGHUsa só cifras fortes

    Configure o FileZilla com TLS Hospedeira
    
          
    A Conexão rápida não serve mais. Abra o Gerenciador de Sites com Ctrl+S, clique em Novo site, dê o nome VM segura e preencha:
    
          
    CampoO que escolher
    ProtocoloFTP - Protocolo de Transferência de Arquivos
    Host · PortaIP da VM, por exemplo 192.168.56.101 · porta 21
    CriptografiaRequer FTP explícito sobre TLS
    Tipo de logonNormal
    Usuário · SenhaO seu usuário e a senha do Linux Mint
    
          
    Clique em Conectar.

    Aceite o certificado Hospedeira
    
          
    Aparece a janela Certificado desconhecido. Confira se o nome comum (CN) é o IP da sua VM e se a instituição é IFSC: são os dados que você colocou no item 1. Marque Sempre confiar neste certificado em sessões futuras e clique em OK.
    
          
    O FileZilla pergunta porque o certificado é autoassinado e nenhuma autoridade certificadora confirmou quem é o servidor. Em produção se usa um certificado assinado por uma autoridade, como o Let's Encrypt.
